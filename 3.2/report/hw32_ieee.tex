\begin{abstract}
This report documents an e-commerce product catalog pipeline:
local CSV extract, Snowflake staging load, dbt staging and timestamp
snapshot with an SCD Type~2 dimension, Airflow orchestration, and four
zero-copy clone demos. A 3{,}000-row catalog was loaded twice; after
mutating 25 products, \texttt{dim\_product} held 3{,}025 rows
(3{,}000 current). Implementation code, evidence dumps, and run scripts
are in the GitHub repository linked below; this PDF is the graded write-up.
\end{abstract}

\begin{IEEEkeywords}
Snowflake, dbt, Airflow, SCD Type 2, zero-copy clone, Time Travel
\end{IEEEkeywords}

\texttt{extract\_products} $\gg$ \texttt{load\_products} $\gg$

\texttt{dbt\_build} runs \texttt{dbt build} via BashOperator.
Verify fails if raw or dim is empty.
CLI twin: \texttt{3.2/scripts/run\_airflow\_tasks.py}.

\subsection{Clone DAG}
\texttt{3.2/airflow/dags/product\_catalog\_clones.py}

dev clone + rated model, point-in-time clone, prototype schema,

\texttt{CREATE OR REPLACE DATABASE \ldots\ CLONE} cannot wipe a sandbox.

\section{Five takeaways}
\begin{enumerate}[leftmargin=*,itemsep=2pt]
  \item Clones share storage until objects diverge; a rated model built
        only in the clone left production unchanged.
  \item Trial Time Travel is one day---use a recent timestamp, not
        2023-12-31.
  \item Timestamp snapshots need \texttt{updated\_at} to advance.
  \item dbt fails on test errors; Airflow extract/verify fail early on
        bad inputs.
  \item Daily \texttt{CREATE OR REPLACE DATABASE \ldots\ CLONE} would wipe
        sandboxes, so clones use a separate DAG.
\end{enumerate}
See also \texttt{3.2/report/takeaways.md}.
